## 2026-08-21 · Windows proxy auto-detection bypass

### Problem
Windows system proxy auto-discovery/WPAD could add several seconds before application HTTP requests started.

### Decision
Configure all production application-owned HTTP clients with `HttpClientHandler.UseProxy = false`. This intentionally trades support for environments requiring a system HTTP proxy for deterministic direct networking; no proxy configuration UI was added.

### Changed
`Program.cs` main and GitHub clients, plus the production fallback constructor in `Services/LocalizationInstaller.cs`.

### Validation
Solution build passed with 0 warnings/errors; 755/755 tests passed; resolver integration passed 13/13; remote CI succeeded for v14.2.3.

### Consequences
API, warmup, localization, official-source, and GitHub requests bypass Windows default proxy/WPAD settings without changing global OS settings.

### Follow-up
No further production network measurement is recorded.

## 2026-08-27 · Managed localization overwrite state hotfix

### Problem
When Black Desert or its launcher replaces `languagedata_en.loc` after BDO-UA Client installed a managed localization, and the game patch did not advance (same `ads_files` patch number), the hash mismatch was classified as `Corrupted`. Production v1.1.2 reproduced: install → game/launcher replaces file → same patch → "Файл локалізації пошкоджено".

### Decision
Existing installation metadata (valid API source, known SHA, file exists but different) proves the managed localization is no longer active — regardless of whether a game patch occurred. Classify this recoverably as `UpdateAvailable` (if current release available) or `WaitingForRelease` (if not), using a new `LocalizationPatchTransition.ManagedFileChanged` value. Higher-patch detection (`GameFileReplacedAfterPatch`) preserved unchanged.

### Changed
- `Services/LocalizationStateResult.cs` — added `ManagedFileChanged` enum value + `WithManagedFileChanged` factory
- `Services/LocalizationStateService.cs` — hash-mismatch fallback: `ManagedFileChanged` → `UpdateAvailable`/`WaitingForRelease` instead of `Corrupted`
- `Services/LocalizationStatePresentation.cs` — added "Встановлена локалізація більше не активна" headline
- Tests: updated 3 existing expectations, added 5 new test cases (same-patch mismatch, no-patch mismatch, same PublicId after change, null current after change, presentation)

### Validation
Release build: 0 warnings, 0 errors. Tests: 805/805 passed (baseline 797 + 8 new). Local preview: `artifacts/local-preview/win-x64/BDO-UA-Client.exe` published. Owner runtime acceptance (2026-08-27): reproduced real launcher-restored-file scenario — after official game/launcher replaced `ads/languagedata_en.loc`, preview correctly showed "Встановлена локалізація більше не активна" + "Доступне оновлення" + "Оновити"; update completed (download, restore point, replace, metadata save); state returned UpToDate; restart remained UpToDate.

### Consequences
No schema/API/installer/backup/rollback change. `ModeCardPresentationPolicy` and `InstallActionPolicy` correctly produce "Оновити" for `UpdateAvailable` state without modification. Roadmap resumes at A.1 GamePaths.

## 2026-08-28 · A.1 GamePaths shared path primitive

### Problem
The Black Desert localization path contract (`ads` directory + `languagedata_en.loc` filename) was duplicated as raw literals and private constants across `GameDetector`, `AdsFilesPatchReader`, `LocalizationInstallService`, `RestoreOriginalService`, `RestoreBackupService`, `BackupStore`, and `MainForm`.

### Decision
Introduce one pure static primitive `BdoClient.Services.GamePaths` owning `AdsDirName` (`"ads"`), `LocalizationFileName` (`"languagedata_en.loc"`), and `GetLocalizationFilePath(gameRoot)` (pure `Path.Combine`). Live game roots use `GetLocalizationFilePath`; backup/restore-point directories use `Path.Combine(directory, LocalizationFileName)` to avoid introducing a spurious `ads\` segment. No validation, IO, normalization, or logging was added.

### Changed
- `Services/GamePaths.cs` (new) — canonical primitive
- `Services/GameDetector.cs` — removed private `LocalizationFile`/`AdsDir` constants; uses `GamePaths`
- `Services/AdsFilesPatchReader.cs` — `GamePaths.LocalizationFileName` for entry comparison
- `Services/LocalizationInstallService.cs`, `RestoreOriginalService.cs`, `RestoreBackupService.cs`, `MainForm.cs` — live game paths via `GamePaths.GetLocalizationFilePath`; restore-point paths via `Path.Combine(..., GamePaths.LocalizationFileName)`
- `Storage/BackupStore.cs` — removed private `SnapshotFile`; uses `GamePaths.LocalizationFileName` / `GetLocalizationFilePath`
- `BdoClient.Tests/Services/GamePathsTests.cs` (new) — 2 focused tests
- Docs: plan marked A.1 COMPLETED, CURRENT.md and this journal updated

### Validation
Release build: 0 warnings, 0 errors. Tests: 807/807 passed (baseline 805 + 2 new). `git diff --check`: only LF/CRLF line-ending warnings (autocrlf), no content issues. Remaining `languagedata_en.loc`/`ads` literals are confined to test fixtures (independent contract verification) and `GamePaths.cs` (canonical definition).

### Consequences
Behavior unchanged; backup/restore-point directory layout unchanged (no `ads\` introduced inside backup storage). Next Stage A task is A.2 source markers (`"api"`/`"official"` constants).
